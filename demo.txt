2. OPENING (1 minute) - what to say
---------------------------------------------------------------------
"This is a multi-organization complaint and ticket portal. Work comes
from two directions: managers create internal tasks top-down, and
students or customers submit complaints bottom-up through a public
portal. Both become the same kind of ticket, with one status flow, one
conversation, one history and one dashboard. Every organization's data
is private - I will show that too."

3. JOURNEY A - SET UP AN ORGANIZATION  (about 4 min)
---------------------------------------------------------------------
1. Normal window -> http://localhost:5173 -> "Create an account".
   Register with any email (e.g. dean@demo.test).
   SAY: "Same answer whether the email exists or not - nobody can probe
   which accounts exist."
2. Terminal 1 -> copy the verify link -> open it -> "Email verified".
   SAY: "The token is in the # part of the link, never sent to the
   server in the URL, and only its hash is stored."
3. Log in -> "Create organization" -> name "Demo University", slug
   auto-fills -> Create. SAY: "I am now Admin. The slug is permanent."
4. Teams -> create "IT" and "Hostel".
5. Categories -> "Wi-Fi", default team IT, Show on portal -> Add.
6. Settings -> "Open the portal" (try it BEFORE step 5 to show it is
   refused without a public category).
7. Members -> invite tech@demo.test as STAFF. Terminal shows the invite
   link. Private window: register tech@demo.test, verify, log in, open
   the invite link -> "Welcome aboard".
8. Teams -> add the new member to IT -> "Make Lead".

---------------------------------------------------------------------

2. Student: "Yes, it's resolved" -> Closed (Completed).
3. Student tries to reply -> not possible, "Submit a new complaint"
   button instead.

   -> reason Rejected -> note is REQUIRED -> "Spam" -> closed.

   refresh the ticket: Closed (Completed), activity says "System".

10. IF SOMETHING GOES WRONG
---------------------------------------------------------------------
- "Invalid environment variables" at start -> check server\.env.
- Health says database disconnected -> start PostgreSQL service.
- Page says "Something went wrong" -> is Terminal 1 (server) running?
- No email in terminal -> ticket emails come within ~15 s (poller);
  account emails (verify/reset/invite) appear immediately.
- "Too many requests" -> rate limit (e.g. 5 wrong passwords); restart
  the server to clear it (limits are in memory).
- EPERM error during "prisma migrate dev" -> stop npm run dev first.
- Seed says "already exists" -> data is there; just log in.
