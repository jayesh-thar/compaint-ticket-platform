=====================================================================
  COMPLAINT & TICKET PORTAL  -  HOW TO TEST EVERYTHING (version 3)
=====================================================================
Rules of the app: README.md section 0. No demo data: you create
everything yourself, starting from an EMPTY database.

---------------------------------------------------------------------
0. ONE-TIME: EMPTY DATABASE + NEW TABLES
---------------------------------------------------------------------
Stop "npm run dev" in the server terminal first (Windows locks a
Prisma file while the server runs). Then in PowerShell:

    cd "C:\Users\Lenovo\OneDrive\Desktop\New folder\server"
    npx prisma migrate reset --force --skip-seed   # deletes ALL dev data
    npx prisma generate

---------------------------------------------------------------------
1. START THE APP
---------------------------------------------------------------------
Terminal 1 (server):
    cd "C:\Users\Lenovo\OneDrive\Desktop\New folder\server"
    npm run dev                      # http://localhost:5000
  -> KEEP THIS TERMINAL VISIBLE. Email is not set up, so every link
     is printed here as JSON:

        ===== EMAIL LINK (console transport) =====
        { "type": "INVITATION", "to": "...", "link": "http://localhost:5173/invite#token=...", ... }

     Types: INVITATION, RESET_PASSWORD, COMPLAINT_TRACKING.
     A failed invitation accept prints "INVITATION ACCEPT FAILED"
     with the reason (wrong account, expired, used, leader taken).

Terminal 2 (client):
    cd "C:\Users\Lenovo\OneDrive\Desktop\New folder\client"
    npm run dev                      # open http://localhost:5173

Several people at once = several browser profiles / private windows
(one person per window, because the login is a cookie).

---------------------------------------------------------------------
2. ADMIN: BUILD THE ORGANIZATION
---------------------------------------------------------------------
1. http://localhost:5173 -> landing page -> Create account -> Sign in.
2. "Create organization" (e.g. Demo Co). You are its Admin.
3. Teams -> create "Server team 01", "Server team 02", "Network".
4. Categories -> New category "Server issue" -> tick Server team 01
   and 02 -> Save. The Teams page now shows them grouped under it.
   (Set its Lead later, once people have joined.)
5. Members -> Invite:
     head01@demo.test  team Server team 01, Leader, Head
     head02@demo.test  team Server team 02, Leader, Lead
     staff1@demo.test  team Server team 01, Member, job title
                       "Network layer security eng." (type it)
     catlead@demo.test no team (will be the Category Lead)
   Each invite prints a JSON block in terminal 1.
6. Settings -> "Open the portal" -> copy the complaint link
   http://localhost:5173/o/<your-slug>

---------------------------------------------------------------------
3. PEOPLE JOIN (one private window each)
---------------------------------------------------------------------
For each invited email: register with THAT email, sign in, then open
its invitation link from terminal 1 -> "Accept".
 - Open the same link again -> "already used" (it expires on use).
 - Open a link while logged in as another email -> refused, and the
   reason appears in terminal 1.
Back as Admin: Categories -> edit "Server issue" -> Lead = catlead.
It shows as "Server issue - Lead".

A team leader (head01) can also invite: open the team page ->
"Invite to this team" (members of their own team only), edit job
titles, remove members.

---------------------------------------------------------------------
4. CUSTOMER COMPLAINT (the full flow)
---------------------------------------------------------------------
1. Any window (no login needed): open /o/<slug>. Fill name, email,
   country code + phone, category "Server issue", subject, problem.
   Submit -> reference T-1 + private tracking link (also in terminal 1
   as COMPLAINT_TRACKING). Open the tracking page: "Received".
2. Admin: Dashboard -> "Pending approval" = 1, the graph's
   "Admin approval" box is red. Open T-1 -> Approve -> category
   "Server issue" (+ priority, deadline). Nobody else saw T-1 before.
3. catlead: Dashboard -> "Waiting for a team choice" -> T-1 ->
   "Send to a team" -> Server team 01.
4. head01: Dashboard "New to my team (assign)" -> T-1 -> Assign ->
   tick two members -> group name -> Assign. (One person = no group.)
   Team page -> Groups tab shows the live group.
5. staff1: Dashboard "Requests to accept" -> Accept -> tick tasks,
   move the progress slider -> "Submit for review".
6. head01: "Needs my review" -> Approve work (or Send back + reason).
7. Admin: "Awaiting final approval" -> Final approval -> Done.
   The group is dissolved; the ticket is in History for the Admin,
   the leader and the members; the customer's tracking page says
   "Resolved". Watch the graph boxes and counts change LIVE in the
   other windows while you do this (no refresh).
Other paths: Admin "Reject" (reason shown to the customer), member
"Decline" (back to the leader), Admin "Move to another team".

---------------------------------------------------------------------
5. INTERNAL TASK
---------------------------------------------------------------------
head01 (or Admin): Tickets -> New task -> team "Network" (or any) ->
priority, deadline, several tasks inside -> Create. It goes straight
to that team's leader (no approval, no category), then the same way
back up: member -> leader approval -> Admin final approval -> Done.

---------------------------------------------------------------------
6. WHO SEES WHAT
---------------------------------------------------------------------
Admin       everything, all dashboards, members, settings, the graph
Cat. Lead   tickets of the category (after approval), the graph
Leader      own team's tickets + history, team page, the graph
Member      only work assigned to them (+ their past work); no graph

Wipe everything again (deletes ALL dev data):
    cd server ; npx prisma migrate reset --force --skip-seed
